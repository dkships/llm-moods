## Edge function gates — history and one-shot invocation procedure

The `isInternalServiceRequest` gate rule came up in Phase 10B when Lovable's curl tool removed the gate from `reclassify-posts` to invoke it (the tool sends user JWT, not service-role) — Phase 11B re-added the gate after a $0.01-per-call attack vector was identified.

If a one-shot reclassify or backfill is needed, the supported invocation path is a **temporary helper edge function**, not raw SQL:

1. Create an ephemeral edge function (slug must NOT start with underscore) that reads `SUPABASE_SERVICE_ROLE_KEY` from `Deno.env` and forwards a Bearer-authenticated POST to the gated function (e.g. `reclassify-posts?mode=multi_model`).
2. Invoke the helper via Lovable's `curl_edge_functions` (which sends user JWT, but the helper itself uses the service-role key for the downstream call).
3. Delete the helper from the deployed function list after the run completes.

**Why not raw SQL:** `current_setting('app.settings.service_role_key', true)` returns NULL in this Supabase environment, and Vault is empty. Pg_cron jobs invoke their target endpoints (`run-scrapers`, `aggregate-vibes`, `cleanup-old-posts`) with the anon key plus an explicit `{scheduler:"pg_cron", pipeline:"<source>"}` body that each function's `isSchedulerRequest` gate accepts — those three were hardened from ungated to this scheduler-body gate in PR #38 (2026-05-24). The service-role key lives only in the edge-function runtime — verified Phase 12.

Gate matrix (as of PR #38, 2026-05-24): `aggregate-vibes`, `cleanup-old-posts`, and `run-scrapers` accept a service-role JWT **or** the pg_cron scheduler body (via `isSchedulerRequest` in `_shared/runtime.ts`); `reaggregate-vibes` requires service-role. A bare anon call with no scheduler body returns 403. The scheduler-body path is what lets the public-repo migration schedule these crons without leaking service-role — see the cron bodies in `20260523120000_public_rpc_security_hardening.sql`. Their operations are still bounded and idempotent, so an attacker who forged the body couldn't escalate beyond the public RPCs anyway.

## Drain, queue, and watchdog mechanics

**Drain throughput (June 1 update — classifier on Claude).** Production classifier is Claude Haiku 4.5 via the Anthropic Messages API (`CLASSIFIER_MODEL=claude-haiku-4-5-20251001`, `ANTHROPIC_API_KEY`). Anthropic Tier 1 limits dwarf our ~30 calls/day, so the Anthropic path has no Supabase quota gate. Drain cadence is 2 min, `limit=200`, `batch_size=20` (~6,000 posts/hr capacity vs ~500-650/day actual ingest — single-scraper-run dumps clear in one pass; current-day score is accurate within ~5 min of the last scraper). `batch_size` was halved from 40 to 20 on May 15 (`20260515160000_drain_batch_size_20.sql`) to cap batch JSON output size. (History: through May the classifier ran on Gemini 2.5 Flash paid Tier 1 with `GEMINI_DAILY_REQUEST_LIMIT`/`GEMINI_MINUTE_REQUEST_LIMIT` raised to 5000/300; those secrets now pace only the free-tier Gemini fallback.) `partial_coverage` is no longer the structural default — `score-refresh.ts` treats `queuedPosts > 5 || classification_coverage < 0.85` as the partial threshold, and `aggregate-vibes` refreshes the last 7 days so those flags heal once the queue catches up.

**Failed-vs-queued split (May 15 update).** `vibes_scores.queued_posts` now counts only `pending + retry` (work the drain will attempt); `vibes_scores.failed_posts` is the dead-letter count (max attempts exhausted, drain ignores). `classification_coverage = classified / (classified + pending + retry)` so the ratio heals when failed posts are recovered. Recover transient failures with `reclassify-posts?mode=reset_failed&error_pattern=transient` (skips deterministic `parse_error`/`missing_*` patterns); confirm with `dry_run=1` first. UI surfaces `failed_posts` as an asymmetric "X abandoned" chip on `/model/:slug` and a top-5-error breakdown panel on `/admin/scrapers`. Pipeline watchdog alerts when posts hit failed status faster than 20/24h.

**Watchdog.** `pipeline-watchdog-1h` writes `severity='critical'` rows into `error_log` on scraper-stale, drain backlog (>500 queued or oldest queued >60 min), aggregate-vibes lag (>90 min), or classification failures piling up (>50). Scraper staleness (fixed 2026-07-01 — since its first commit it matched short names like `reddit` against `scrape-*` slug run rows, so it fired 5 spurious criticals/hour while real staleness was invisible) now runs two per-source arms keyed on the actual `scraper_runs.source` slugs: last run older than 14h (`scrape-reddit-apify`, 2×/day cadence) / 11h (the 3×/day scrapers), and last `success`/`partial` run older than 30h (catches a scraper that runs on schedule but fails or budget-skips every window — the May Reddit failure mode). The runs query looks back 72h so the 30h arm can't false-fire while today's run is still in flight. Surfaced via `get_critical_alerts(hours_back)` RPC into the `/admin/scrapers` banner (note: that RPC redacts message text, so verify watchdog changes by invoking the function directly with the scheduler body and reading the returned `alerts` array) and a calm `StalenessBanner` on the public dashboard when the newest `score_computed_at` is >3h old. `error_log` gained a `severity` column ('info' | 'warning' | 'critical', default 'info') in migration `20260510120100_pipeline_watchdog.sql`.

**Accepted risk — scheduler-gate spoofability (2026-07-01 audit).** The `{scheduler:"pg_cron", pipeline:"…"}` body + public anon key can invoke the scheduler-gated functions (scrapers, drain, aggregate-vibes, aggregate-rumors, cleanup-old-posts). Deliberate tradeoff: it keeps service-role out of public-repo migrations and doubles as the manual-diagnosis path. Exposure is bounded by the Apify budget caps, drain idempotency, and the rumors lock. The proper fix (Vault-stored secret header wired into every cron job) touches cron migrations plus multiple redeploys — schedule as its own hardening session if the calculus changes.

## Classifier — routing, retry, spillover, self-bias

Sentiment is classified by **Claude Haiku 4.5** (`claude-haiku-4-5-20251001`) via the Anthropic Messages API (forced-JSON via tool use; `temperature` is omitted — current Claude models reject it). `_shared/classifier.ts` routes by model-id prefix: `claude-*` → Anthropic native path, everything else → Gemini's OpenAI-compatible endpoint. The active model is `CLASSIFIER_MODEL` (falls back to legacy `GEMINI_CLASSIFIER_MODEL`, then `gemini-2.5-flash`); `getClassifierApiKey()` picks `ANTHROPIC_API_KEY` vs `GEMINI_API_KEY` to match — so a model swap is a pure config flip and **rollback = set `CLASSIFIER_MODEL=gemini-2.5-flash` (no redeploy; both providers stay live)**. Single-model posts use `classifyBatch()`; multi-model posts use `classifyBatchTargeted()` for per-model sentiment (e.g., "DeepSeek fixed Gemini's mess" → negative Gemini, positive DeepSeek). Retry: 3 attempts, exponential backoff; Anthropic 429/529 are treated transient. The Anthropic path runs batches with bounded concurrency (`ANTHROPIC_BATCH_CONCURRENCY`, default 4) and no inter-batch sleep, and the drain writes rows back concurrently; the Gemini path stays serial with a 2s inter-batch delay and its quota early-break (commit 091310c). Strict tool use (`strict:true`) is intentionally NOT enabled — our nullable-union / null-in-enum schema 400s under the structured-output JSON-Schema subset (verified in prod 2026-06-02); forced `tool_choice` carries the JSON shape. Re-enabling needs an `anyOf`-based nullable rewrite plus live-API testing. Non-English posts are translated by the classifier prompt; original in `content`, translation in `translated_content`, language code in `original_language`. Prompt caching applies on Sonnet/Opus (≥1024-token cacheable prefix) but not Haiku (4096-token minimum) — fine, Haiku is cheap (~$8/mo modeled vs ~$22/mo Sonnet). Known limitation: the classifier (Claude) is itself a tracked model, so pro-Claude self-bias is the measurement risk; cross-checked via the Gemini second grader in `check-gemini-self-bias` (run around classifier changes, not always-on; Opus was dropped from `DEFAULT_CANDIDATES` 2026-07-06 so a bare invocation can't silently bill 300 posts at Opus rates — pass it via the `candidates` body param when wanted). On transient Claude errors `classification-state.ts` spills failed items over to Gemini using `GEMINI_API_KEY`. **There is no separate `GEMINI_FREE_API_KEY`** — the spillover and the `check-gemini-self-bias` oracle both use the paid `GEMINI_API_KEY` (owner accepts the small cost; Gemini is cheap). The spillover is bounded by its own quota bucket (`GEMINI_FREE_MINUTE_REQUEST_LIMIT`/`GEMINI_FREE_DAILY_REQUEST_LIMIT`, default 8/min, 200/day — raise via Lovable env if a prolonged Claude incident needs more headroom). Both depend on billing being active on the `GEMINI_API_KEY` Google project. Claude-path classification verified live 2026-06-01 (131 posts, 0 errors).

`reclassify-posts` edge function supports `?mode=multi_model` to find and fix historical multi-model posts with identical sentiment. Run `reaggregate-vibes` after to recalculate scores.

**2026-07-10 accuracy-audit changes (classifier):** input cap raised 600→2000 chars (`CLASSIFY_INPUT_MAX_CHARS`) so long Reddit self-posts keep their sentiment-bearing tail (~$1-2/mo extra Haiku input); `BATCH_CLASSIFY_TARGETED_PROMPT` (the ONLY prompt production uses — the other two run in manual reclassify modes only) re-synced with the rules the other variants had (RELEVANT examples, category NOT-clauses, "even if the overall tone is positive" switching qualifier, sarcasm example), plus three new rules: outage/status posts are NOT relevant, an IMPLICIT TARGET rule pairing with the "(posted in r/X)" context prefix `modelMentionText` now adds for reddit rows and the "(N/5 star App Store review of the X iOS app)" suffix from scrape-appstore, and a fix for the contrast-pattern bullet that referenced a nonexistent "MIXED" sentiment. Neutral guidance changed from "should be RARE / lean toward the expressed emotion" to genuine-mixed calibration (scoring now counts neutral as 0.5, not 0.3 — see vibes-scoring). Batch bodies pass through `sanitizeBatchText` (quotes → apostrophes, `[TARGET:`/`Post N:` framing tokens defused) and a results array LONGER than the batch is now a batch-wide retryable `result_count_mismatch` parse_error instead of silently-trusted positional alignment.

## Scraper actor details

**Reddit scraper** uses the `harshmaur/reddit-scraper` Apify actor (HTML-parsing, residential proxy; config-driven via `scraper_config.actor_id`). One actor run **per subreddit**, fanned out in parallel (`actor_concurrency=8`) so the whole run fits the edge function's hard 150s request limit, across 8 subreddits (ClaudeAI, ClaudeCode, ChatGPT, OpenAI, GeminiAI, grok, plus the cross-vendor leak hubs r/singularity + r/LocalLLaMA — a net-zero swap in `20260623120000_rumors_radar.sql` from the redundant ChatGPTPro/GoogleGemini, for the rumors radar; the two leak hubs are intentionally NOT in `SUBREDDIT_MODEL_MAP`, so they attribute only via the codename/version `model_keywords`). harshmaur is **pay-per-event** ($0.02 Actor-start fee per run + $0.002/item) — the per-subreddit fan-out pays that start fee 8×/window (~$8/mo). A **`single_run_mode`** path exists behind the `single_run_mode` config row (default off; request-body `single_run:true` override) but was **validated NO-GO on 2026-07-06**: with all 8 subs in one run, harshmaur spent the entire total `maxPostsCount` cap on the first-listed subreddit (`per_subreddit_items: {ClaudeAI: 80}`, $0.164) — first-sub starvation applies to posts-only runs too, not just comments. **Do not enable it with this actor.** The code stays as telemetry + a ready path for a future actor with per-URL caps (e.g. fatihtahta); the fan-out's 8×$0.02 start fees (~$8/mo) are the accepted price of even coverage. **Posts only** — `max_posts_per_sub=10`, `poll_timeout_secs=100`. Comment ingestion is built but **disabled** (`include_comments=false`): the first live run showed harshmaur comment items don't carry the subreddit, so attribution failed and ~302 comments/run dropped for ~$0.76 of wasted spend; re-enable only with a comment→parent-post attribution fix. Cost ~$0.30/run. The old `trudax~reddit-scraper-lite` died with Reddit's `.json` API shutdown (May 2026).

**Twitter/X scraper** uses `apidojo~tweet-scraper` Apify actor with `searchTerms` array input — **exactly 5 queries** as of `20260706120000_twitter_query_consolidation.sql`: ChatGPT sentiment (isolated so the highest-volume model can't starve the rest), merged Claude+Gemini+Grok sentiment, combined rumor term, leaker/reverse-engineer roundup, press roundup. Query inclusion is discovery only; credibility keys on the author handle and evidence in `_shared/rumor-canon.ts`. The roundup includes vetted leakers plus discovery-only accounts, and `20260712120000_rumor_source_expansion.sql` adds artifact researchers Fried_rice + pankajkumar_dev and reporter haydenfield without adding a query. Five is deliberate: apidojo bills a **50-tweet minimum per query** (query count, not `max_items`, dominates cost — 8 queries had a $0.16/run floor above the $0.15 cap) AND the actor documents "up to 5 batched queries" per run (more is undocumented behavior). `max_items=250` retrieves the already-billed 5×50 floor; `maxTotalChargeUsd=$0.15/run` remains the hard cap. Has a dormant Grok/xAI fallback path (requires `XAI_API_KEY`). Apify budget: $29/month plan. Guard defaults in `_shared/apify-budget.ts` are $24/mo + $0.80/day, but the **live env overrides are `APIFY_MONTHLY_SPEND_LIMIT_USD=28` + `APIFY_DAILY_SPEND_LIMIT_USD=2`** (verified from a run's `apifyBudget` block 2026-07-06 — read the response, don't trust the in-code defaults). Used for Reddit and Twitter. Both actors are **pay-per-event** — `maxTotalChargeUsd` is the authoritative cost cap (the `maxItems` run-option is largely inert on PPE).

**Hacker News scraper** (free Algolia, no key): stories pass now reads `story_text` so Ask HN / Tell HN self-posts ingest as `title_and_body` (full scoring weight), and a second pass queries `tags=comment` for the same 5 neutral terms — comments are where HN model-experience sentiment lives; a comment must itself name a model to match (`matchModels` on comment text, no community shortcut), capped at `MAX_COMMENTS_PER_RUN=60` (~$1-2/mo Haiku).

**Mastodon scraper**: the `/api/v2/search` phrase-query pass was removed 2026-07-10 — unauthenticated full-text search returns HTTP 200 with empty `statuses`, so it contributed zero posts on every run while looking healthy (re-adding needs a free Mastodon app token as a new secret). Request budget went to per-model hashtags on the four tech instances (`TECH_HASHTAGS` now includes claudeai/geminiai/grok, fixing the chatgpt-heavy imbalance).

**App Store review scraper** (`scrape-appstore`, added 2026-07-10, free/keyless): Apple customer-review RSS (`itunes.apple.com/us/rss/customerreviews/id={APP}/sortBy=mostRecent/page=1/json`) for the four iOS apps (ChatGPT 6448311069, Claude 6473753684, Gemini 6477489729, Grok 6670324846 — verified live). 100% personal-experience content, symmetric across models. Attribution is direct (review of the Claude app = claude); the star rating + app name ride in the content suffix so the classifier gets implicit-target context and app-shell complaints (login/billing/crashes) classify irrelevant per the outage/status rule. Capped at `max_reviews_per_app` (config, default 15) per run so ChatGPT's ~160-review/day feed can't dominate. Cron `scrape-appstore-3x` at the standard three windows.

**Twitter `max_items` raised 80→250** (2026-07-10 migration): the 5-query set bills a 50-tweet/query floor (~250 tweets) per run regardless, so the 80-item dataset fetch discarded already-billed tweets with query-order bias; `maxTotalChargeUsd=$0.15/run` stays the hard cap.

## Rumors radar — full pipeline

- **Intake (additive):** `_shared/rumor-detect.ts` `isLikelyRumorCandidate()` and `_shared/release-detect.ts` `isReleaseAnnouncement()` are OR'd into every social scraper's news-drop check so leak and launch posts survive (they still classify `irrelevant`, so vibes scores are unaffected). Codename/next-version `model_keywords` rows let `matchModels` attribute "Fable 5"/"Honeycomb"/"Orionmist" etc. These rows and the `FAMILY_ALIASES` + `COMPETITOR_DENY` seed data in `_shared/rumor-canon.ts` are ephemeral; refresh them each cycle. Bluesky has free targeted searches for current labels/codenames and stores author + quote identity. Twitter stores the same fields for echo/origin collapse.
- **Canonicalization + filtering (`_shared/rumor-canon.ts`, zero-import, Deno-free, used by BOTH backend write-time and frontend display-time):** `canonicalVersionKey` collapses maintained aliases (Fable / Mythos / "Mythos/Fable 5" → one `fable5` row). Identity components also learn links explicitly observed in rows: a row containing label `Opus 5` + codename `Honeycomb` connects codename-only Honeycomb rows without a manual alias. `isNonFrontierLabel` drops competitor names + non-family labels while keeping novel codename-only claims open. Source cleanup removes strict hypothetical/speculative legacy evidence, recovers missing handles from URLs, and collapses repeated accounts plus shared quote origins. Unit-tested in `src/test/rumors.test.ts`.
- **`aggregate-rumors` edge fn (hourly cron, gated + service-locked):** Phase 1 — `get_rumor_candidates` (distinct-`source_url`, leak-lexicon `~*` gate, author + quote identity) → Haiku `record_rumors` forced-tool extraction (**N claims per post**; strict OFF for nullable enums; ~10/batch; prompt forces `unknown` for other makers; never invents an ETA). The extractor labels `claim_mode` and `evidence_kind`; `buildContribution` rejects sentiment, jokes, wishes, unsupported comparisons/hypotheticals, inference without evidence, and confidence below 0.55. Phase 2 groups contributions using maintained aliases plus learned label/codename bridges, collapses account/quote echoes, then upserts `model_rumors`. `mention_count` means independent origins, up to 12 representative sources are retained for cross-run dedup, and delayed/return remain sticky lifecycle states.
- **Retiring launched models is mostly automatic.** The radar is for *unreleased* versions only. Retirement runs at two layers, both landing in `model_rumors.is_released` (added `20260702090000_rumors_auto_release_detection.sql`), which `get_public_rumors` filters on (`is_released IS NOT TRUE`):
  - **Auto (backend, in `aggregate-rumors` each run):** ① **Models APIs** fetch Anthropic + Gemini shipped IDs and derive `version_key` tokens (`_shared/released-models.ts`). ② **Official feed** parses Product items from OpenAI's public news RSS and accepts only explicit GA wording; preview items do not count. ③ **Social** accepts a "generally available now" post from a credible source, then derives model tokens directly from the announcement text. This is the xAI/codename backstop (`_shared/release-detect.ts`; a limited/EAP release does not count). Detected tokens flip `is_released=true` on matching rows via a bounded `UPDATE`. Counts land in the run's `error_log` summary (`released_from_api`, `released_from_openai_feed`, `released_rows_flagged`) for audit.
  - **Manual instant layer (frontend, `isReleasedVersion` in `_shared/rumor-canon.ts`):** set `released: true` on a `FAMILY_ALIASES` entry to hide a launch on the next `main` sync with zero backend deploy — used mainly for codenames whose shipped public name differs from the tracked key (e.g. Bidi), the one residual manual touch. Family-agnostic + family-stem strip ("Claude Sonnet 5" caught). Default-false, so it never denies a novel leak.
  - There is **no** `is_unreleased` column. The accumulator holds unreleased rows by construction; `is_released` retires ones persisted before launch (they also age out via 21-day decay). OpenAI needs no key because its official RSS is public. xAI has no key in the secret store, so its launches use the social layer plus the manual alias fallback.
- **Frontend:** `useRumors` → `get_public_rumors` → `mergeRumorRows` cleans legacy rows immediately, then applies the independent-source gate. One vetted/artifact source can surface; untracked chatter needs two independent origins across two platforms or three origins on one platform. Artifact/curated evidence ranks above lifecycle urgency and volume, so a weak "imminent" claim cannot replace a stronger in-testing artifact. Cards show independent-source counts. ETAs remain unconfirmed community estimates, never forecasts.

## Frontend patterns catalog

- **Vendor events overlay on charts:** `src/data/vendor-events.ts` exports `VENDOR_EVENTS[]` (typed-TS, frontend-only). `VibesChart` accepts an optional `events` prop and renders Recharts `<ReferenceArea>` / `<ReferenceLine>` for each one. Used to mark Anthropic / OpenAI / Google / xAI bug windows, model launches, and postmortems.
- **Per-model product surface tagging:** `src/lib/product-surface.ts` carries a per-model regex map (e.g. Claude → Claude Code / Claude.ai / API / SDK). Display-only — applied client-side to recent posts; no schema change.
- **Anomaly detection:** `src/hooks/useScoreAnomalies.ts` runs a 14-day rolling z-score in the browser over `vibes_scores`. Surfaced in the dev-only `/admin/scrapers` Anomalies panel and cross-referenced against Official Status events on `/model/:slug` via `src/lib/status-correlation.ts`.
- **Official Status integration:** `supabase/functions/fetch-vendor-status` parses Anthropic + OpenAI Atom feeds and Google Cloud incidents.json, returns the last 30 days. `useVendorStatus()` + `<StatusCard />` render the result in the left column under the chart for all four model pages. xAI shows a "no public status feed" empty state.
- **Research articles:** `src/data/research-posts.ts` carries typed-TS `ResearchPost` entries with markdown bodies. The body's ```chart-model``` fenced code block is intercepted by `src/components/research/EmbeddedModelChart.tsx` and replaced with a live model chart. Article + Dataset JSON-LD emitted via the extended `useHead.jsonLd` field. `src/components/research/AuthorBio.tsx` is the single source of truth for David's bio + contact links — its `BIO_LINKS` array drives every article's footer; update there, not per-article. `src/components/research/PullQuote.tsx` styles verbatim social-post citations (handle / platform / timestamp meta + optional `archivedHref` for Wayback backups); use in place of `<blockquote>` when the quote is load-bearing evidence. **The research surface is a deliberate editorial register, not dashboard chrome:** `src/lib/prose-styles.ts` keeps accent inline links / code, an accent blockquote left-rule, and 17px paragraphs by design (a Tailwind-Typography scale, not drift). The four research components (`PullQuote`, `StatCallout`, `AuthorBio`, `EmbeddedModelChart`) use the global type ladder for their chrome labels (`text-mono-cap` / `text-meta`, standardized in Round 3 PR #36) but keep that editorial accent on links / quote marks / citation links — don't neutralize it to match the calmer dashboard, which would flatten the articles (the portfolio surface).
- **Per-route static OG HTML (prerender):** `scripts/prerender-routes.ts` is a Vite plugin (`closeBundle`) that writes a transformed copy of `dist/index.html` for every public route (articles, model pages, dashboard, research index, privacy) in both `<route>/index.html` and `<route>.html` forms, so LinkedIn/Slack crawlers (no JS) see per-route title/OG/canonical/JSON-LD. **Lovable's host serves these only at the literal `.html` paths** (extensionless and trailing-slash URLs always get the SPA shell — verified in prod 2026-06-12), so social shares must use the `.html` form (e.g. `llmvibes.ai/research/<slug>.html`); an inline head shim rewrites the path back to the clean route via `history.replaceState` before React boots. New public routes must be added to the plugin's route table AND `public/sitemap.xml`.
